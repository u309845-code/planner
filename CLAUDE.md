# Planner

Личный веб-планер на русском языке: задачи, дедлайны, календарь, заметки, учёт времени, отчёты.
Видение продукта — в `docs/vision.md`, команды — в `docs/commands.md`.

## Стек
- `web/` — React + TypeScript + Vite + Tailwind CSS, иконки lucide-react
- Supabase: вход по email и паролю, Postgres (таблицы `tasks`, `time_entries`), права через RLS
- Хостинг: GitHub Pages (https://u309845-code.github.io/planner/), сборка и выкладка — `.github/workflows/deploy.yml` при `git push` в `main`

## Команды (из папки `web`)
- `npm.cmd run dev -- --host 127.0.0.1` — тестовая версия на http://127.0.0.1:5173
- `npm.cmd run build` — проверка типов и сборка
- `npm.cmd run lint` — линтер

## Структура
- `web/src/App.tsx` — каркас, разделы, данные для экранов
- `web/src/store.ts` — работа с Supabase (задачи, журнал времени, таймер, повторы)
- `web/src/components/` — экраны и части интерфейса (Today, Week/Month, TasksBoard, Notes, Reports, Time)
- `web/src/dates.ts`, `stats.ts`, `recurrence.ts`, `calendar.ts`, `csv.ts` — чистая логика без интерфейса
- `supabase/schema.sql` и `supabase/migrations/NNN_*.sql` — изменения базы; выполняются вручную в Supabase → SQL Editor по порядку

## Правила
- Секреты (ключи, пароли) не хранятся в коде. `web/.env.local` не попадает в git. Публичный ключ Supabase (publishable) допустим в коде и в workflow.
- Любое изменение таблиц — новый файл в `supabase/migrations/` и сообщение пользователю, что его нужно выполнить **до** деплоя.
- Перед `git push` проверить, что нужные колонки есть в базе (иначе сайт перестанет сохранять задачи).
- Деплой делается только по просьбе пользователя.
- Интерфейс спокойный: цвет только у сроков (красный — до 1 дня, жёлтый — до 3 дней), детали прячутся до нужного момента.
- Время хранится в UTC, показывается в местном часовом поясе; «день в плане» — локальная дата `ГГГГ-ММ-ДД`.
- Тексты интерфейса на русском, без родовых окончаний.
- В сообщениях коммитов не использовать двойные кавычки (PowerShell ломает аргументы).
